# Project instructions

Use short, direct English in documentation, UI text, comments and commit messages.
Follow ASD-STE100 sentence structure. Use one instruction per sentence.
Keep instructions within 20 words and descriptions within 25 words where practical.
Use technical terms when needed. Explain uncommon terms.
Avoid slogans, marketing claims, semicolons and “not X, but Y” comparisons.
Preserve uncertainty, test conditions and legal scope.
Do not claim full ASD dictionary compliance without a dictionary review.

Use git-cad for CAD management, Monad System for website UI, and Hawa for CFD.
Read project/tools-and-optimization.md before changing those integrations.
Use Monad tokens and components. Keep its vendored files unchanged.
Record upstream versions and retain third-party licenses.
Rebuild website reference pages after documentation changes.
Label planned work, calculations, simulations and physical measurements.

This site is the owner's collaborative build journal.
Keep public project descriptions brief and descriptive.
State the owner's equipment and constraints as facts about this build.
Do not add operator requirements, competition rules, formal acceptance gates or transport instructions.
Keep technical experiments in context with the build's current progress.
